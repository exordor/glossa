# 0004 撤销重做：v0.1 用 tldraw 的历史栈，数据层提供删除与恢复

- 日期：2026-11-09
- 状态：采用（jiale 不在线时按推荐项决定，可推翻）。

## 背景

计划第 8 步要求撤销重做覆盖画布操作和 AI 生成。画布上的卡片是 tldraw shape，数据在 `@reader/core`。
两套撤销栈会互相打架：tldraw 已经处理了拖动、删除的撤销，界面上的撤销按钮和快捷键也是它的。

## 决定

1. 撤销栈只用 tldraw 的一个。`@reader/core` 不另建撤销栈，只提供可逆的数据操作：
   - `deleteNodes(ids)`：删节点，连带删连到它们的连线；删掉的内容（含 `nodes/<id>.md` 正文）留作内存墓碑，保存时删文件。
   - `deleteEdges(ids)`：只删连线。
   - `restore({nodes, edges})`：从墓碑原样恢复。随节点删掉的连线，两端都回来时自动恢复。
   - 新事件 `node.deleted`、`node.restored`。
2. 界面监听 tldraw 的 shape 增删（用户来源，包括撤销重做），排队同步到数据层：卡片被删就 `deleteNodes`，卡片回来就 `restore`。
3. 什么进撤销栈：
   - 只有「新建卡片」和用户自己的拖动、删除进历史。
   - 卡片内容更新（流式写回答）和连线 shape 都不记，连线永远按数据层重建。
   - 打开书时建的卡不记，并清空历史，免得一按 Cmd+Z 清空画布。
4. 一次动作（解释、钉到画布等）开始前打一个停止点，这次建的摘录卡、回答卡合成一步撤销。
5. 撤销正在生成的回答：取消请求；之后重做回来的卡标成「已中断」，可重试。

## 代价与后续

- 撤销栈只在当前页面内存里，关掉书就没了；CLI / MCP 没有撤销。v0.2 做 CLI 时，如需跨端撤销，再把历史下沉到 core（操作日志）。
- 用户在 tldraw 里画的原生图形（箭头、文字）不进数据层，和以前一样。
- 删除卡片不追问「是否连带删除下游卡」：只删选中的卡，下游卡保留、连线断开。可以撤销，所以先不加确认框。
