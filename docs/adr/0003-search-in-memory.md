# 0003 Cmd+K 搜索：v0.1 先做内存匹配，FTS5 推后

- 日期：2026-11-09
- 状态：采用（jiale 不在线时按推荐项决定，可推翻）。

## 背景

计划第 8 步写的是「Cmd+K 搜索（FTS5）」，设计文档把 SQLite FTS5 当作派生索引。
v0.1 只有网页界面，数据通过开发期 bridge 读写本地文件；在浏览器里跑 SQLite 要引入 wasm 包和索引同步，成本远大于收益。
一本书通常几章、几百张卡，逐条匹配在毫秒级。

## 决定

1. `@reader/core` 的 `search(query, entries)`：查询按空白拆词，所有词都出现才算命中，NFKC + 小写折叠；卡片略优先，词在开头附近加分。
2. 条目来源：原文按段落切（`paragraphEntries`，出处写「章 › 小标题」），卡片取标题 + 正文。打开搜索时现取，不建索引。
3. 接口固定为「条目进、命中出」。以后 CLI / MCP / 跨书搜索要上 FTS5 时，只替换实现，界面不动。

## 后续

- CLI（v0.2）落地时把 FTS5 索引放进 `.canvas/index.sqlite`，作为可重建的派生数据，不进版本库。
- 中文目前是子串匹配，不分词；够用前不引入分词器。
